# @living-diorama/built-in-content

The pre-built world and species, registered through `extension-api` exactly as a third-party pack would be.

## Owns

- The `hollow` pack: the Woodland Hollow world, the wooden bridge structure, the mossling species ([ADR 0005](../../docs/adr/0005-world-content-and-walkability.md)) and the five prop types its world places: pine, round tree, rock, bush and mushroom. Mushrooms and bushes offer `core:food` and round trees `core:shelter` ([ADR 0018](../../docs/adr/0018-living-behavior.md) §3).
- Four prop categories for the editor's prop drawer ([ADR 0021](../../docs/adr/0021-live-prop-editing.md)), each prop type in one: trees (pine, round tree), rocks, plants (bush) and mushrooms.
- The core voxel part types (torso, head, leg, arm, tail, ear, eye, nose, mouth, fin; the tail has the `tail` role) and the socket types they fit ([ADR 0022](../../docs/adr/0022-voxel-creatures.md) §10), in `woodland-hollow/voxel-parts`. The parts themselves come later.
- `sampleVoxelAssembly()`, a sample voxel creature of box parts built in code, for the app's development console and the headless tools. It is exported, not registered: no world or species of the pack uses it, since the pack ships no test creature.
- The files that content refers to, registered as `assets` ([ADR 0007](../../docs/adr/0007-renderer.md)): prop models from Kenney's Nature Kit (CC0, `woodland-hollow/assets/models/LICENSE-kenney.txt`) and the mossling's placeholder appearance image, from which its body is extruded ([ADR 0011](../../docs/adr/0011-extruded-creature-bodies.md)).
- `woodland-hollow/world.json`, generated by `pnpm worldgen` from the layout in `tools/development/src/worldgen`. Never edit it by hand; a test fails if it drifts from the generator.

## Must not

- Use any registration path that a third-party pack could not use.
- Be imported by engine packages. Only the app composition root (and dev tools) may import it.

## Workspace dependencies

`@living-diorama/content-schema`, `@living-diorama/extension-api`

Boundary rules are enforced by `pnpm boundaries` (dependency-cruiser) and `pnpm lint`; see roadmap §1.4.
