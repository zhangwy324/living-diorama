# ADR 0018: Living behavior

- **Status:** Accepted
- **Date:** 2026-10-28
- **Context:** Roadmap §3.2 step 5. Creatures today only wander (ADR 0006 §9): props block movement and offer nothing, behaviors see the whole world, and there is no time of day. Step 5 gives creatures needs they meet in the world, so that later work (drawn senses and needs, structures, saves, the Chronicle, the inspector) has a shared vocabulary: needs, affordances, senses and traits, events, individual state and time. The decisions build on the existing decision framework (ADR 0006 §7–§8: behaviors propose scored actions, the engine validates) and are taken against the fixed built-in world. Step 5 lands as a series of PRs: **1** this ADR; **2** schema and registries (§1–§4); **3** time, night lighting and the needs engine (§5–§9); **4** food, perception and memory (§10–§12); **5** shelter, sleep and home (§13–§14); **6** tuning, long-run tests and the hand check (§18). Each PR updates this ADR where it departs from it. All numbers were starting values, tuned in PR 6. All PRs have landed (#83–#98 and #99), so the decisions below, as amended, describe the code. The owner's hand check (the manual checklist in [development](../development.md)) passed on 2026-10-28, the in-app 20-creature performance spot check (Exit, below) is deferred to issue #68 with only headless numbers so far, and step 5 is not released (see _Amendments_).

This ADR amends ADR 0002 (prop placements and the new `prop` kind), ADR 0004 §7 (traits and senses arrive) and ADR 0006 §8 (triggers and interruption).

## Decisions

### Vocabulary

1. **Needs are registry entries holding data.** A new `needs` registry in `extension-api`. A need's value runs from 0 (met) to 1 (pressing), the same way round for every need, so utilities compare directly. A need declares how fast it rises per hour of simulation time while awake and while asleep, and the value at which a creature starts to act on it (`actAt`). Step 5 registers two, in the core pack beside the core actions:
   - `core:hunger`: rises from 0 to 1 in 90 minutes; `actAt` 0.4. With travel and eating that is a meal every 30–60 minutes. It rises at half speed while asleep.
   - `core:tiredness`: rises from 0 to 1 in 16 hours awake, falls to 0 in 8 hours asleep; `actAt` 0.7. The day phase adds to it (§13), so creatures sleep at night and nap when tired by day.

   Comfort and curiosity are left out: comfort needs environment fields and weather, and `core:wander` keeps playing curiosity's part. A creature has the needs its behaviors depend on (a `needs` dependency in the behavior's `dependencies`), so a species with only `core:wander` has none and behaves as today.

2. **Affordances carry parameters.** An affordance on a structure or prop type is a map from affordance ID to its parameters, checked against a parameter schema the affordance type registers (`AffordanceType` gains `params`). Structure types change from a list to the same map (`{ "core:crossable": {} }`). Step 5 adds:
   - `core:food` `{ eatSeconds }`: a creature may eat here. A source never runs out (§12).
   - `core:shelter` `{}`: a creature may sleep beside it.

   The engine finds food and shelter by affordance, never by prop or model ID.

3. **Prop types.** A new definition kind `prop` (schema version 1): `id`, `version`, `name`, `model`, `blockRadius` and `affordances`. A prop placement names its type (`prop: ContentId`) and keeps only its `id` and `transform`; `blockRadius` moves to the type. The 108 Woodland Hollow placements share five types. Mushrooms and bushes are food, round trees are shelter, pines and rocks offer nothing. Structures stay the concept for anything that adds regions or connections.

4. **Senses and traits are species maps** (ADR 0004 §7), registered in new `senses` and `traits` registries.
   - `senses: Record<ContentId, number>`. As with capabilities, a missing sense means the creature lacks it. Step 5 has one sense, `core:vision`: its range in metres.
   - `traits: Record<ContentId, number>`. A trait left out takes the default its registry entry declares. Step 5 has `core:nocturnal` (0 sleeps at night, 1 sleeps by day; default 0) and `core:appetite` (scales hunger's rise; default 1).
   - The mossling gets `core:vision: 8`. Drawn species get the same defaults (ADR 0014 §11's `DRAWN_SPECIES_DEFAULTS`), plus `core:feed` and `core:rest` in their behaviors. Step 8 reads these from the drawing instead.

### Time and decisions

5. **Time of day is an input, not a clock read.** The main thread sends `set_time_of_day { minutes }` (local minutes since midnight) once a minute and on resume, queued and applied at a tick boundary like any other command (ADR 0006 §11), so a run stays replayable from its command log. The simulation maps it to four phases: dawn 06:00–08:00, day 08:00–18:00, dusk 18:00–20:00, night 20:00–06:00. A dev setting fixes the time of day so night can be tested at noon. Needs run on simulation time, so the speed multiplier speeds them up. The phase stays with the input time.
   - **Two clock modes, one built now.** _Real time_ (step 5): the time of day is the OS clock, as above. _Custom day_ (later, with a settings control): the player sets a day length, and the time of day is simulation state advanced by ticks and saved with the world, so the main thread sends nothing. Everything downstream reads only the time of day, so the custom mode adds a clock source and changes no behavior. Which need rates then scale with the day length (tiredness surely, hunger perhaps not) is decided when it is built.

6. **Night lighting.** The snapshot carries the time of day. The renderer blends the sun's colour, intensity and height and the sky light between a few keyed times, so dusk and dawn are gradual. The Studio's preview keeps today's daylight.

7. **Two new decision triggers.** Behaviors are still evaluated only on triggers (ADR 0006 §8). Step 5 adds a need crossing its `actAt` upwards and the day phase changing.

8. **Interruption by utility, with a margin.** A running action remembers the utility it was chosen with. On a new trigger the behaviors are evaluated. A proposal replaces the running action only if its utility is at least 0.15 higher, and the interrupted action fails with `interrupted`, as from the watchdog. With no action running, the highest proposal wins as before. The margin, and needs that act only above `actAt`, keep goals from flickering.

9. **Utilities.** `core:wander` stays at 0.1. `core:feed` proposes with `0.2 + hunger`, `core:rest` with `0.2 + tiredness + night bonus` (§13). Proposals start only above `actAt`, apart from the night bonus. A creature that is both hungry and tired goes for the more pressing need.

### Food

10. **Vision and memory.** Once a second, a creature with `core:vision` looks for props with affordances within its range. Range is a straight-line distance with no line-of-sight test (terrain occlusion is later). It remembers what it has seen: up to 8 food and 4 shelter placements, each with the tick it was last seen. The oldest entry is forgotten first. A creature without vision learns about a place only by bumping into it, within 1 m. Pathfinding still knows the real geometry (spec §8.3). Only knowledge is partial.

11. **`core:feed` (behavior) and `core:eat` (action).** When hungry, `core:feed` picks the remembered food with the shortest route. `core:eat` takes the placement ID: it walks to the nearest walkable spot within reach of the prop (`blockRadius + creature radius + 0.3 m`), eats for `eatSeconds` and lowers hunger by 0.8. Knowing no food, `core:feed` proposes `core:follow_path` to a random point, preferring regions the creature hasn't visited recently (a short list in its memory), which is how it discovers food.

12. **Food never runs out.** Any number of creatures may eat at a source, any number of times, so food adds no world state. Portions, depletion and regrowth (and their events) are later, when there is a reason for creatures to compete or move on; adding them then means a `portions` parameter on `core:food` and per-placement state in `WorldState`.

### Shelter and sleep

13. **`core:rest` (behavior) and `core:sleep` (action).** The night bonus is 0.5 in the creature's sleeping phase (night, or day for `core:nocturnal` 1) and 0.2 at the edges of that phase (dusk and dawn). The bonus alone can start sleep, so creatures go to bed at night even when not very tired. `core:sleep` walks to a shelter spot (as in §11), then stays still until tiredness is below 0.1 and the creature's waking phase has begun, or tiredness reaches 0 during a nap. Hunger can wake a sleeper only above 0.9. A creature that knows no shelter sleeps where it stands.

14. **Home.** The first shelter a creature sleeps at becomes its home (`new_home_selected`). `core:rest` prefers home over closer shelters unless home is more than twice the route length of the nearest one, and then it naps there without changing home. Home is a placement ID in the creature's state.

15. **Visible cues, no need readouts.** An action type may declare a `cue` (`"eating"` or `"sleeping"`), and a need may declare one with the value it shows from (`core:hunger`: `"hungry"` from 0.8). The snapshot carries each creature's cues. The renderer shows a small bob while eating, a still, slightly lowered body with rising "z" sprites while sleeping, and a small bobbing food bubble above a very hungry creature, without knowing action or need IDs. Need values, memory and home go into the snapshot only with debug on, for the dev overlay. The inspector comes later.

### Individuals, events and catch-up

16. **Individual state and variation.** Creature state gains `needs` (ID → value), `memory` (seen food and shelter, recent regions), `home` and `variation`. Variation is drawn once at spawn from the creature's own RNG stream and stored: hunger and tiredness rates and vision range each scaled by 0.85–1.15. Everything stays plain data (ADR 0006 §4), and `CreatureInstance` is widened to match in step 6. Spawned creatures start with random needs below their `actAt`, so they don't all eat at once (tiredness below its `startBelow` of 0.1, from PR 6).

    _Amended by [ADR 0019](0019-world-saving.md) §2 (M15 PR 1):_ `CreatureInstance` was replaced rather than widened. Creatures are saved as `CreatureSave` entries of `WorldSaveSchema` in `content-schema`, which mirror `CreatureState`.

17. **Events.** New events: `ate`, `fell_asleep`, `woke_up` and `new_home_selected` (per creature), and `day_phase_changed` (a world event, with no `creatureId`; the event base is split into creature and world events). The decision trace gains the need values and each proposal's reason.

18. **Sanctuary.** No deaths and no harm. A creature whose hunger reaches 1 walks at 80% speed and doesn't wander until it eats. That is the only consequence.

19. **Catch-up in real time mode, built in step 6.** Step 5 changes nothing within a session: the clock still drops time beyond `maxCatchUpTicks` (ADR 0006 §1), and only the time of day jumps on resume. When step 6 restores a saved world in real time mode, the gap is not simulated; the world is set to a plausible state for the present:
    - the gap is wall-clock time since the save, capped at 12 hours. A clock that went backwards counts as no gap, and a gap under 2 minutes runs as ordinary ticks;
    - tiredness: if the gap covered the creature's sleeping phase, it is rested (0); otherwise it rises by the hours spent awake;
    - hunger: the creature is assumed to have eaten, so it gets a random value below `actAt` (integrating the gap would leave every creature starving after a long absence);
    - the action in progress is dropped. A creature is placed asleep at home if it is now its sleeping phase, otherwise at a random reachable point in its home's region (its current region if it has no home);
    - catch-up emits no per-creature events. The Chronicle gets one summary later.

    In custom day mode there is no catch-up: the world carries on exactly from the state it was saved in.

    _Amended by [ADR 0019](0019-world-saving.md) §6:_ a gap under 2 minutes is no gap, not ordinary ticks: the world is restored exactly and only the time of day jumps.

    _Amended by [ADR 0019](0019-world-saving.md) §5 (M15 PR 3):_ "covered the sleeping phase" is applied as integration over the phases the gap passed through: tiredness falls at the asleep rate during the creature's sleeping phase and rises at the awake rate otherwise, and is reset to 0 when a sleeping phase ended during the gap.

### Testing

20. **Long-run checks.** The randomized invariant runs (ADR 0006 §12) also check that needs stay in [0, 1], that every creature with reachable food eats at least once per simulated 3 hours, that creatures spend most of the night asleep, and that decisions per creature stay under a bound (no flicker). A headless runner option prints, per creature, meals, sleep hours and time spent hungry.

## Amendments (2026-10-28)

Agreed with the owner before implementation. Where these and the decisions above differ, these hold. Each PR adds an "as built" note at the end where it departs further.

### Vocabulary

- **§1, tiredness:** `actAt` is 0.9 and tiredness rises from 0 to 1 in 18 hours awake, so dusk (§13), not a nap at 17:00, sends a creature to bed. It still falls to 0 in 8 hours asleep.
- **§1, hunger asleep:** hunger rises at a tenth of its awake rate while asleep (a fifteenth from PR 6), not half, so a creature sleeps through the night.
- **§1 and §7, triggers:** a need declares a list of trigger values, ascending and including `actAt` (`core:hunger`: 0.4, 0.9, 1). Rising across any of them starts an evaluation. A crossing of `t` is `previous < t && current >= t`, so the trigger at 1 fires even though the value is clamped to 1.
- **§1, §15 and §18, need data:** a need also declares its cue (`core:hunger`: `"hungry"` from 0.8) and its effect at 1 (`core:hunger`: `atMax: { speedFactor: 0.8 }`), so §18's slower walk is data, not code. Need cues (`hungry`) and action cues (`eating`, `sleeping`) are separate lists, so a need can't declare an action's cue.
- **§2, affordance entries:** `AffordanceType` gains `paramsSchema`, as a surface type has, and an optional `remember` cap. `core:food` remembers 8 and `core:shelter` 4, so §10's caps come from the entries, not from IDs.
- **§3, block radius:** `blockRadius` lives on the prop type and is multiplied by the placement's `transform.scale` (amends ADR 0005 §8). Navigation is otherwise unchanged.
- **§3, prop types:** the registry is named `props`. The five types are `hollow:pine`, `hollow:round-tree`, `hollow:rock`, `hollow:bush` and `hollow:mushroom`, with display names. `eatSeconds` is about 5 for a mushroom and 10 for a bush.
- **§3 and §4, schema versions:** the world and structure schemas go to version 2 and `prop` starts at 1. A species gains optional `senses` and `traits` (default `{}`) without a species version bump.
- **§4, ranges:** a sense or trait entry declares `default`, `min` and `max`, and a species' values are checked against them when references resolve. An entry may also declare `integer: true`, and then a species value must be a whole number: `core:nocturnal` takes only 0 or 1.
- **§4, appetite:** a need may declare `rateTrait`, a registered trait whose value scales both of its rates. `core:hunger` declares `core:appetite`. The engine reads the link from the need, never from the trait's ID.
- **§16, variation as data:** a need or sense may declare `variation`. Each individual's rates (need) or value (sense) are scaled by a factor drawn once in [1 − variation, 1 + variation]. `core:hunger`, `core:tiredness` and `core:vision` declare 0.15. The engine applies it to whichever entries declare it, without branching on IDs.
- **§4, drawn species:** the library entry migration from version 1 to 2 adds `core:feed`, `core:rest` and `senses: { "core:vision": 8 }` to stored drawn species.

### Time and decisions

- **§5, time input:** `init` carries the current minutes. `set_time_of_day` follows every minute and on resume: unpausing, the window becoming visible and an OS wake, seen as a jump in wall-clock time. Headless and test runs derive the time of day from simulation time and a configurable start.
- **§5, fixed time:** the dev setting is a dev-only console hook, like `dev-library.ts`: `livingDiorama.time.set("21:30")`, `.follow()` and `.speed(20)`.
- **§5 and §13, phases:** for a creature that sleeps at night, the waking phase is dawn and day and the sleeping phase is night, with dusk and dawn as the edges. The end of sleep is checked every tick, so a nap that runs into night becomes night sleep.
- **§8, interruption:** a challenger must beat the running behavior's current utility, evaluated again at the trigger, by 0.15. Proposals from the behavior that owns the running action are ignored, so it never interrupts itself. Behaviors that aren't chosen evaluate on a scratch copy of memory, and only the chosen one's memory and RNG use is kept. If a scratch copy proves impractical, the noise is accepted and recorded here.
- **§9 and §18, wander:** `core:wander` doesn't read hunger. `core:feed`'s utility at hunger 1 beats it on its own.
- **ADR 0006, watchdog:** the stuck watchdog counts only ticks on which the action walked (`context.walk()`), so standing still to eat or sleep is not being stuck.
- **§11 and §13, changing needs:** actions change needs through `context.adjustNeed(id, delta)`. Hunger falls gradually over `eatSeconds`, so an interrupted meal counts in part. An action reports an explicit `asleep` flag, which selects the need rates.
- **§15, cues while walking:** an action's cue shows only while the creature isn't walking.
- **§17, phase events:** `day_phase_changed` is not emitted at init. A jump across several phases emits it once, with `from` and `to`.
- **§19, short gaps (2026-10-28, [ADR 0019](0019-world-saving.md) §6):** a gap under 2 minutes is no gap, not ordinary ticks: the world is restored exactly and only the time of day jumps.

### Food and shelter

- **§10 and §16, knowledge:** the new per-creature field holding seen food and shelter and recently visited cells is `knowledge`. The existing `memory` keeps its meaning.
- **§10, §11 and §13, cost:** candidates are filtered by straight-line distance first, and only the best 2–3 are pathed. Each creature reacts to a phase change after a random 0–30 s, and the 1 Hz perception scan is staggered across creatures.
- **§10, touch:** learning by touch within 1 m is built now. Only a test fixture species without vision exercises it.
- **§11, exploring:** exploration prefers cells of a coarse 8 m grid not visited recently, kept in `knowledge`, instead of regions.
- **§11 and §13, spots:** a creature eats or sleeps at its own seeded angle around the prop, falling back to the nearest walkable spot.

### Presentation

- **§6, night lighting:** lighting is keyed at about six times of day. Night is a moonlit blue-grey in which creatures stay readable, with a dim moon opposite the sun still casting soft shadows, a refitted shadow camera and a blended background colour. The Studio preview stays in daylight. The owner reviews screenshots at four times of day before merge.
- **§15, cue rendering:** cues are procedural sprites sized in screen pixels, with a minimum. Sleeping lowers the body by about 10% with a slow breathing scale and rising z's, eating bobs, and hungry shows a food bubble. The owner reviews a capture.
- **§15, debug:** with debug on, small 3D text labels above each creature, in the renderer's overlay group, show its needs, knowledge and home.

### Product and process

- **§13, release grace:** a creature doesn't sleep in the first 10 minutes after it is released from the Studio.
- **§13, bedtime (owner, 2026-10-28):** bedtime follows the start of the sleeping phase, not dusk. Only the sleeping phase's bonus (0.5: night, or day for a nocturnal creature) can start sleep on its own. At the edges (dusk and dawn) the 0.2 bonus only adds to a creature already tired enough to act on tiredness. So creatures settle over dusk only if they are really tired, and most go to bed as night begins (after the 0–30 s phase reaction), for about 10 hours of sleep.
- **§20, test runs:** `pnpm check` runs a short set (a few seeds, one simulated day at about 2 Hz) and `pnpm soak` the full set. The golden trajectory test is regenerated, and soak's expectation that every creature crosses the bridge changes if it must.
- **§20, decision bound:** on average at most about one decision per creature per 10 simulated seconds, and at most 3 interruptions per minute.
- **Exit:** step 5 is done when eating bobs, hungry bubbles, creatures sleeping with z's near round trees and homes are visible; dusk and dawn change smoothly and the Studio stays in daylight; the debug overlay shows needs, knowledge and home; `pnpm check` and `pnpm soak` pass with the §20 checks; a 20-creature spot check shows no regression against [performance](../performance.md); a manual checklist entry is added and run by the owner; and this ADR records every departure.
- **Release (owner, 2026-10-28):** step 5 does not ship as v0.3. No release is cut for it; the next release is decided later.
- **PRs:** step 5 lands as 2a needs, senses and traits registries; 2b prop types; 3a time of day and 3b night lighting, in parallel; 3c the needs engine, which also defines the snapshot's cues (`CreatureSnapshot.cues`); 4a food, 4b cue rendering, 4c the long-run harness and 4d the debug overlay, in parallel; 5a shelter, sleep, home and the release grace; 5b drawn species defaults and the library migration; 6 tuning, the §20 checks, docs, the manual checklist and performance.

### As built

- **PR 2a:** a need's rates are `perHour: { awake, asleep }`, signed, so tiredness asleep is −1/8. Cues are fixed vocabularies in `extension-api`, `ACTION_CUES` and `NEED_CUES`, and `simulation` re-exports their types so the renderer needs no `extension-api` dependency. `ActionType` gains an optional `cue`. `core:vision` ranges over 1–30 m and `core:appetite` over 0.5–2. The affordance params schemas live in `content-schema`, and `core:crossable` gets an empty one. Structures still list their affordances, so params are checked only from PR 2b. Drawn species get empty `senses` and `traits` until PR 5b. All starting values.

- **PR 2b:** prop types are registered in `props`, and a placement is `{ id, prop, transform }`. A structure's or prop type's affordances are a map whose params are checked against each affordance type's `paramsSchema` when references resolve. A prop's block radius is the type's `blockRadius` × the placement's `transform.scale`, which amends ADR 0005 §8 (block radius in world metres, not scaled). The world model resolves each placement into a `PropModel` carrying its scaled block radius and its type's affordances. The renderer's `SceneData.props` carries only the ID, model, transform and block radius (`SceneProp`), so the renderer still knows no prop types. The type radii are the generator's former per-scale radii (pine 0.3 m, round tree 0.35, rock 0.5, bush 0.4, mushroom 0), and Woodland Hollow's placements are unchanged. Placements used to store the product rounded to the millimetre, so an effective radius now differs from the stored one by at most 0.5 mm. That moves one walkability cell for the small and large size classes in the east meadow, and no medium cell. The generator still spaces props by the rounded radii, so the scatter is the same.

- **PRs 3a and 3b, time of day:** the world state holds the time of day as given (`minutes`, wrapped into a day) and the phase as of the last tick. Each tick compares the two, so `day_phase_changed` comes from the tick, not the command: several commands before one tick count as one jump, and a jump that ends in the phase it started in emits nothing. That comparison is where PR 3c's phase trigger goes. World saves (step 6) must keep both `minutes` and `dayPhase`, or loading a save would emit a spurious phase change. The main thread checks the clock every 5 s and sends `set_time_of_day` when the minute has changed or the wall clock jumped, before `resume` on unpausing and when the window becomes visible. While paused, the worker answers `set_time_of_day` with a snapshot so the light still follows. Headless runs set the time each tick from a start (default noon; `pnpm sim --start 21:30`). The renderer lights the diorama from `snapshot.timeOfDay`, so the console hook `livingDiorama.time` replaces PR 3b's `livingDiorama.setTimeOfDay`. The lighting keys are spread wider than the phases, with the owner's approval: night lighting is fully in at 20:30 although the night phase starts at 20:00, and the light begins to brighten from 05:00. Besides §6's sun colour, intensity and height and sky light, the light's side, the background colour and the shadow strength vary with the time of day too.

  _Amended (2026-10-29, [issue #127](https://github.com/zhangwy324/living-diorama/issues/127)):_ WebView2 throttles timers on a hidden page, so the 5-second check fell a minute or more behind while the strip was hidden, and every late check counted as a jump. The clock is now checked on the worker's snapshots, which keep coming while the strip is hidden (ADR 0019 §4 amendment, issue #117), at most every 5 s of wall-clock time. A jump is counted only when consecutive snapshots are more than 15 s apart in wall time or the clock went backwards, and then the time is sent at once. The 5-second timer stays as a backstop while paused, when no snapshots come, so the paused world's light still follows the clock; a late timer check never counts as a jump.

- **PR 3c, needs engine:** a behavior that reads a need declares it as a `needs` dependency, and a creature has exactly the needs its species' behaviors declare, so a species that only wanders has none and moves exactly as before (its trajectories are unchanged, also across phase changes). Creature state gains `needs`, `knowledge` (`places` per affordance ID, capped by the entry's `remember`, the oldest seen forgotten first, and `recentCells` of the 8 m grid, at most 8), `home` (null), `variation` (per need and per sense) and `asleep`. Variation and starting needs are drawn from a stream forked off the creature's own (`"individual"`), and each creature's phase-change delay from one forked per change, so neither shifts what its behaviors draw. Senses are scaled by the variation without clamping to the sense's range. Each tick a creature's action steps first, then its needs change, then triggers are checked; several on one tick (every trigger value crossed, and the phase reaction) make one evaluation, whose trace lists them all in `triggers`. Every behavior is evaluated on a copy of its memory and of the creature's random stream, also when no action runs, and only the chosen one's copies are kept, so a scratch copy proved practical. Behaviors in one evaluation therefore see the same draws, and memory written by a behavior that isn't chosen is lost, so cooldowns must come from the observation. An evaluation that chooses nothing (no proposal, or the running action kept) advances the creature's stream by one draw, so a retry or the next trigger doesn't replay the same draws. When an action runs, the bar is its owner's current utility, or 0 if the owner proposes nothing; a challenger that wins but fails to start leaves the action running, and an interrupted action ends as `interrupted` with the reason `outranked`. Behaviors see the running action and its owner in the observation (`action`). An evaluation that keeps the running action is traced with the result `kept`, and traces gain the triggers, the need values, the bar and each proposal's `reason`. The watchdog counts ticks on which the action walked without progress, so `ActionProvider.moves` is gone. Any call to `walk`, even on a path already finished, counts as walking for the watchdog and hides the action's cue. An action reports `asleep` and its cue on each step; the cue shows only if the action type declares it and the action didn't walk that tick. The snapshot's `cues` list the action's cue first, then need cues. `adjustNeed` ignores a need the creature lacks and a non-finite change. The worker protocol goes to version 7.

- **PR 4a, food:** the world model parses each prop's affordance params with the affordance type's `paramsSchema` when it is built, freezes them, and indexes props by placement ID and by affordance (`propsByAffordance`). Perception is engine code, run at the start of a creature's tick once a second, at a tick offset hashed from the creature's ID. For each affordance with a `remember` cap it notes the props within vision (straight-line distance to the prop's centre, the individual's variation applied) or within 1 m of the prop's edge, by touch. Touch works for every creature, not only one without vision. A scan notes at most the cap's nearest places, so it never forgets what it has just seen, and it records the 8 m cell the creature stands in. Every creature perceives, also one that only wanders, whose moves stay unchanged. Behaviors see places through `WorldQueries.place`, `spotAt` and `routeLength`, and actions through `ActionContext.place` and `spotAt`. Actions emit events through `ActionContext.emit`, which adds the tick and the creature, and turn the creature with `ActionContext.face(x, z)`. A creature's spot angle is drawn once at spawn, last from its `"individual"` stream, and stored as `spotAngle`. It uses the same angle at every place. The spot lies at block radius + creature radius + 0.3 m. If no reachable walkable cell holds it, the creature takes the centre of the nearest reachable walkable cell within 1.5 m of it. If there is none, it tries the same an eighth of a turn on, and so on round the prop. Only cells whose surface lies within 0.75 m of the prop's base height count, and where regions overlap the one nearest that height wins. `core:feed` proposes from `actAt`, and while its own action runs it returns `0.2 + hunger` at any hunger, so a meal isn't cut short once hunger falls below `actAt`. The three nearest known foods by straight line get a route, and the shortest route wins (`chooseNearestByRoute`, which takes the affordance ID, so `core:rest` can reuse it). Food the creature failed to reach (the eat failed to start, or the watchdog stopped it) is skipped for 60 s, through `core:feed`'s memory, which is kept because `core:feed` was the chosen behavior. A challenger that fails to start now sets `lastResult` to its failure while the running action carries on, so a behavior learns of the failure in either case. To explore, it draws up to 8 random reachable points (`WorldQueries.randomWalkablePointWithin`) at least 4 m away and within twice its vision range (at least 8 m; 12 m without vision), and takes the first in a cell not in `recentCells`, or else the one in the cell visited longest ago. - **PR 4b, cue rendering:** a creature's pose carries the cues of the snapshot it blends from, and the newest snapshot's once it arrives, so cues don't lead the body. Each cue fades in and out (eating 0.4 s, hungry 0.5 s, sleeping 1.2 s) on real time, so a creature that appears while paused still fades its cues in, while the bob, breathing and z's run on the paused clock and hold still. After a gap of over a second (a hidden page) the cues snap to the current ones. Eating lifts the body by up to 4% of its height and dips its front by up to 0.12 rad, about once a second, so the bob reads as a peck; the tilt turns about the feet, so the body also rises by its front's drop and a long body never dips into the ground. Each creature has its own phase, so neighbours don't move in step. Three z's rise at a time from a sleeping creature, drifting right on screen; a hungry creature shows a speech bubble with a drawn mushroom, which steps left when z's rise too and fades out while it eats (back after the meal if it is still hungry). The sprites are drawn from signed distances into data textures, so they need no canvas, are unlit and drawn over the scene (a bubble behind a tree would say nothing), and their size is a share of the creature's height on screen, at least 22 px for the bubble and 13 px for a z, in CSS pixels. - **PR 4c, long-run harness:** the §20 checks live in `tools/development/src/long-run-checks.ts`, and every invariant run uses them. Each tick every need must be in [0, 1]. A decision is any traced evaluation, `kept` and `rejected` included, and each creature may make at most 1 per 10 simulated seconds on average over its life, plus its first. An interruption is a trace that started a challenger while an action ran, since interruption emits no event. The stuck watchdog's ends don't count, and at most 3 may fall within any 60 simulated seconds. Wander alone decides about 0.4 times per 10 s in Woodland Hollow but about 1.3 in the small river-crossing fixture, whose walks are short, so runs there loosen the bound to 2 (`maxDecisionsPer10Seconds`). Only a `started` evaluation ends the run, and `kept` does not count. The meal check counts the `ate` events of each creature and fails a gap of more than 3 hours. The sleep check fails a creature asleep for less than half the night ticks it lived through, once it has lived through an hour of night. Both are options that stay off until PR 6, which also chooses the creatures they apply to, since only those that can reach food should be held to the meal check. - **Cue occlusion and clipping (#93, PR 1):** this amends PR 4b's "drawn over the scene". The terrain and structures now hide the cues of a creature they hide from the camera; props, trees and other creatures still never do, as PR 4b's reason holds for them (a bubble behind a tree still belongs to a creature in view). The sprites are still drawn over the scene with depth testing off; instead each creature with a cue gets a visibility weight that multiplies every cue's opacity. Against structures it casts a `Raycaster` at the structures layer, where only the decks are on the raycast layer: railings are too thin to hide anything. The cues hide only when every point is hidden, so a creature partly in view shows its cues in full, with no see-through state. A changed result must hold for 2 checks before the cues follow it, and they then fade over 0.4 s; the first check after a cue starts applies at once, and a creature without cues isn't checked. - **Cue declutter (#93, PR 3):** where creatures bunch up, their bubbles and rings are pushed apart on screen, and sleepers whose z's overlap let fewer rise. Each frame the renderer projects each creature's head top to CSS pixels and works out where its bubble's or ring's round body would be (a circle of the texture's outline radius, including the bubble's step left while z's rise). In up to 4 passes, every pair that overlaps, with a 2 px margin, is pushed apart along the line between them, each by the other's share of their weights (fade times visibility), so a faint cue hardly moves a clear one; two on the same spot send the earlier one left. A shift never goes down into the creature's head and never further than the cue's own size, about one bubble width. Cues showing less than 0.05, hidden ones included, neither push nor are pushed: their target is no shift. Each frame's target is worked out afresh from unshifted positions, and every shown shift eases towards it with a 0.2 s time constant on real time, so it is the same at any frame rate and nothing jumps as a cue fades across 0.05: one fading in eases out from where it is, and one fading out eases back. A gap longer than a second snaps. The z's are not pushed. Instead a sleeper whose z column (a rectangle from where its z's start to where they finish rising) overlaps an earlier sleeper's by more than 30% of the smaller column thins to one z, until the overlap drops below 15%; the first sleeper keeps its full count. The thinning lowers the same target count as PR 2's size rule, so the change waits for the next z. Creatures are laid out in ID order, so the result is stable and doesn't depend on the order poses arrive in. The vertical model is approximate: the layout measures the gap and the body's height above the head in screen-up pixels, while `CueSprites.place` puts them along world +Y, which the camera's downward tilt shortens a little on screen, and the bubble's bob is ignored. The layout keeps its working values on each creature's record, made once per creature, so by design it allocates nothing per frame; no test checks this. With 20 creatures bunched in one spot, half hungry and half sleeping, a frame of `CreatureBodies.update` goes from about 7 to about 10 µs, measured headless in Node. All starting values.
- **Turning in place (#94):** this amends PR 4a's and PR 5a's facing. `ActionContext.face(x, z)` no longer turns at once: it and the new `turnTo(heading)` turn the creature the short way round by at most `TURN_RATE` (π rad/s, half a turn a second) per tick, and return `"turning"` or `"facing"`, so an action calls them every tick until it faces the way it wants. - **Bedtime with no known shelter (#122):** this amends §13's and PR 5a's "sleeps where it stands". A creature that wants to sleep but knows no shelter it can reach first looks for one: `core:rest` proposes `core:follow_path` (now one of its dependencies) to a point it can reach within 6 m, then 12 m, then 20 m (`SHELTER_SEARCH_RADII`, straight line from where it then stands), each at least half its radius away, at the same utility it would sleep with; while a search walk runs it returns 0.95 to continue it, as for its sleep. A radius with no such point in 8 draws is skipped. Perception goes on as it walks, so when a walk ends, a shelter it saw or touched on the way wins as usual and can become its home. After the third walk, or after its last sleep failed to start or got stuck (no search then), it sleeps in the open. The count of walks is the behavior's memory (`searches`, `searchedAtTick`), so it is saved without a schema change. It clears when the creature goes to sleep at a shelter, but not when it sleeps in the open: a search that found nothing counts for 12 hours after its last walk (`SEARCH_FORGET_SECONDS`), so a creature woken in the night, by hunger say, or napping the next morning, lies down in the open again at once, and the next bedtime searches afresh. In the open, no two creatures lie on the same point: `core:sleep` without a shelter checks, every tick until it lies down, whether another creature asleep is closer than the two body radii plus 0.3 m (`SLEEPER_GAP`), and if so walks to the first of 12 points drawn within 3 m, then 12 within 6 m, that is clear (`clearSpot`), at most 3 times (`OPEN_SPOT_MOVES`, saved as `moves` in its state), then lies down anyway. Creatures lie down one at a time within a tick, so of two settling on one point the second sees the first. Catch-up uses `clearSpot` too: a creature that knows no shelter is put to bed where it stands, or at a clear point close by if a creature put to bed before it lies too close; all creatures count as awake until put to bed. For this `WorldQueries` and `ActionContext` share `OpenGroundQueries` (`randomWalkablePointWithin`, moved there, and the new `sleeperNear(position, gap)`), `CatchUpResult.start.at` may be a position, which the engine accepts only if the creature has a route there (`no_route` otherwise), and `ActionStart` may say `asleep`, so a creature started asleep counts as asleep before its first step. Sleeping in the open is not yet worse than at a shelter. Sleepers at a shelter keep their own spots and don't check; as built since #158 they do (bullet below).
- **Food it failed to reach (#95):** this replaces PR 4a's fixed 60 s skip in `core:feed`'s memory. Failures now live in the creature's knowledge: a remembered place may carry `failures { noRoute, stuck, retryTick, cell }`, counting since the creature last reached it. `core:eat` reports through the new `ActionContext.noteReach(affordanceId, placementId, outcome)`: `no_route` when its start finds no spot or route, `stuck` when the watchdog stops it before it arrives, and `reached` when it arrives at its spot, which clears the failures. An outranked meal records nothing. `stuck` is the failure that happens in practice. `no_route` is a guard that is rarely hit, since `core:feed` proposes only places it has just found a route to. Each failure backs the place off until `retryTick`: 30 s for the first `stuck` and 120 s for the first `no_route`, doubling with each further failure of that kind, at most an hour (`REACH_BACKOFF_SECONDS`, `MAX_REACH_BACKOFF_SECONDS`, starting values). A shorter back-off of one kind never shortens a longer one of the other. `core:feed` leaves out places still backed off before ranking by straight line, and keeps no memory. `routeNearest` (`chooseNearestByRoute`, which `core:rest` shares) now passes over known places without a spot the creature can reach, such as food across water from a walker, and counts only places with a spot towards the three that get a route, so an unreachable place can't hide a reachable one further away. Perception clears a place's no-route count when it notices the place from a grid cell other than the one the creature failed from, and the creature has a spot there it can reach; the whole record goes only if the creature never got stuck there. If it has no such spot, that cell becomes the failures' cell, so each cell is asked about once. Stuck failures clear only on arriving: a spot and a route existed when the creature got stuck, so seeing the place again proves nothing, and clearing them would let a wandering creature retry at the base back-off forever. Failures are not otherwise forgotten, except with the place itself. There is no fallback to another spot at the same place: a spot is already the nearest reachable one. A creature that keeps getting stuck on its two nearest foods tries each about six times in half an hour instead of over twenty. The world save goes to version 2.
- **Shelter it failed to reach (#161):** shelter trips back off like food trips (#95). `core:sleep` reports through `noteReach` under `core:shelter`: `no_route` when its start at a shelter finds no spot or route, `stuck` when the watchdog stops it before it arrives, and `reached` when it arrives at its spot. When it then finds no shelter but at least one it knows is backed off, `core:rest` sleeps in the open at once without searching, as after a sleep that just failed or got stuck; searching is for a creature that knows no shelter. Catch-up ignores back-off, as it places the creature rather than walking it there, and doesn't record `reached` either. The back-off times are food's.
- **Shelter that keeps failing (#171):** this amends §14 and the #161 bullet above. A known shelter the creature has failed to reach at least twice since it last did (`noRoute` plus `stuck`, `SEARCH_AFTER_SHELTER_FAILURES`) is failing. Once every shelter it knows is failing, home included (a forgotten home has no failures, so it never is), `core:rest` searches as a creature that knows no shelter does, in both cases where #161 sleeps in the open at once: after a sleep that just failed or got stuck, which is the case that fires at bedtime, since a back-off of at most an hour rarely outlasts the evening, and when every shelter it could choose is backed off. `chooseShelter` passes a failing shelter over for any that isn't, and chooses one only if no other can be chosen; a failing home then counts as any other shelter, without the home preference. Only places that still offer `core:shelter` count as backed off or failing, so a place that has stopped offering shelter no longer holds back a search. Catch-up is unchanged: it ignores failures and back-off, records none, never searches, and doesn't re-home. A slow swimmer that gets stuck just after jumping into water can stay stranded there, as its way out starts with the same swim; that is a navigation matter outside this change.
- **Sleepers at one shelter (#158):** this amends the last sentence of the #122 bullet: sleepers at a shelter now keep apart as in the open, at least the two body radii plus `SLEEPER_GAP` (0.3 m), centre to centre. `PlaceQueries.spotAt` takes an optional `{ clearOfSleepers: gap }`, and `findSpot` a `clear(position)` predicate: a spot another sleeper lies too close to is passed over for the next of the 8 angles round the place, and a shelter with no clear spot left is full. Feeding asks for spots as before. `core:sleep` takes the first clear spot at the start, and every tick until it lies down checks whether a sleeper now lies too close to the spot it walks to or stands at; if so it heads for the next clear spot. A shelter found full, at the start or on the way, makes it sleep in the open near its spot there: it walks on to that spot and moves away from the sleeper there as #122 does (`placementId: null` from then on, with `full: true` in the start's detail when found full at the start). Nothing is recorded for a full shelter: no failure or back-off, no `reached`, no home and no re-homing. `chooseShelter`, and so `routeNearest` when it asks, passes a full shelter over, home included, without changing home; with every shelter it knows full, `core:rest` goes on as for knowing none, so it searches first. Catch-up does the same: `catchUp` passes the clear spot as a position in `start.at`, a full home or nearest shelter counts as none, so the creature lies down in the open, and `startAsleep` checks the creature stands at that same clear spot. Creatures put to bed before it count, as in the open. The long-run catch-up check now expects a sleeper with a home at its spot there clear of the others asleep, or elsewhere if home is full (`Simulation.spotFor` takes `spotAt`'s options). In the tests, four of eight mosslings fit at one round tree in Woodland Hollow, live and in catch-up alike.
- **Catch-up at a failing shelter (#175):** this amends the #171 bullet's "Catch-up is unchanged". `catchUp` passes a failing shelter over as it does a full one, home included: home if home isn't failing and has a clear spot, else the nearest shelter by route that is neither failing nor full, else the open, by `clearSpot`. Unlike `chooseShelter`, it never falls back to a failing shelter: a creature isn't put to bed where live play keeps failing to take it. It still reads failures only, ignores back-off, records nothing, never searches and doesn't re-home, so a creature put to bed elsewhere keeps its failing home. `startAsleep` is unchanged: the engine starts it only at the spot `catchUp` chose. The long-run catch-up check (`catchUpProblems`) now finds any sleeper at a shelter it is failing to reach, and no longer expects one with a failing home to lie there (`isFailingShelter`, exported for it).
- **Sleep from night to night (#85):** this amends §5's and PR 5a's fixed phase starts for creatures. Each creature lives its own day: the world's four phases with their starts moved by an offset drawn uniformly within ±30 min (`DAY_SHIFT_MINUTES`, a starting value) from a stream forked off the creature's own (`day@<tick>`). One offset a day, drawn at the start of the creature's own dawn, moves that evening's dusk and night at once, and the next dawn and day once its night has begun. The offset that moves a phase start is so fixed hours before it, so a new draw never puts the creature back into the phase it has just left. Its first morning's offset is drawn at spawn, last in the `individual` stream. The engine keeps it in `CreatureState.day { phase, morning, evening? }`, not in `core:rest`'s memory, which is kept only when rest is chosen; the world save goes to version 3. `creaturePhaseStarts` is the one function that moves the phases: it turns the baseline (the world's phase starts) and the offsets into absolute starts, which `dayPhaseAt` and `minutesToNextPhase` both read from one sorted table, so they agree to the last bit at a moved start. A user's baseline sleep window (#101) belongs there, and can move a start by hours. Behaviors and actions see the creature's own phase as `dayPhase`, and the day-phase decision trigger (with its 0–30 s delay) fires when that phase changes, not when the world's does; `day_phase_changed` still follows the world, as the light does. So the dusk and dawn edge bonus and the night bonus move with the offset, and `core:rest` is unchanged: by its own day phase a creature still needs tiredness 0.9 (`actAt`) to sleep, so the offset never puts it to bed in the world's day. Catch-up walks the gap through the creature's own day (`creaturePhaseSpans`), drawing a dawn's offset the gap passed as the ticks would have, so `tirednessAfter` and the asleep-or-awake choice use its own phases. Self-correction is the tiredness carry-over that was already there, with no new mechanism: tiredness at bedtime is what the day awake since waking made it, so a creature that woke early goes to bed more tired, and every night rests it fully hours before its dawn, so a late night carries nothing into the next day and the offsets, drawn afresh each day, can't drift. A test checks both. The long-run checks now fail a creature that sleeps at night falling asleep in the world's day below `actAt`, and `pnpm sim` reports each creature's bedtimes and wake times. Over 10 days with 4 mosslings (seed 1), bedtimes fell at 19:32–20:27 and wakes at 05:31–06:28, 41–54 min apart per creature, against 20:00–20:02 and 06:00 before. For a nocturnal creature the draw is also at its own dawn, which is its bedtime edge: the engine knows no sleep cycle, and it is still one bounded offset a day.
- **The food it wants (#110):** this amends PR 4b's and #93's single food icon. An action may name the placement it goes to or uses (`ActionProvider.target(state)`; `core:eat` names its food), and the snapshot carries it as the creature's optional `cueTarget` while a need's cue shows and the behavior that chose the action declares that need as a dependency. So a hungry creature walking to food names the food, and one going to a shelter while hungry names nothing. It is absent while exploring for food and once hunger falls below the cue's 0.8. It is read from the action's state when the snapshot is made, so saves, determinism and the worker protocol's version are unchanged (an optional field, like `cueProgress`). The renderer draws each loaded prop model once into a small texture (128 px, multisampled, mipmapped) in a fixed daylight of its own, from about 35° above in a three-quarter view, framed to the model's bounds, and shows it over a bubble without its icon, as a sprite 0.62 of the bubble's width that fades and moves with it. Until the picture is drawn, for a model that failed to load, and with no target, the bubble keeps the neutral food icon. The picture keeps its target while the bubble fades out, and changes at once when the target does. No content or schema changed: the picture is the prop's own model, so the renderer knows no content IDs.

## Consequences

- Behaviors stay data-light code, and needs, affordances, senses and traits are data, so step 8 can set senses and traits from a drawing without new engine code.
- Prop placements break (`blockRadius` moves to the type). No migration is needed (AGENTS.md: backward compatibility).
- The worker protocol version goes up (new command, snapshot fields and events).
- Perception is a linear scan of about 100 props per creature per second, which is cheap at 20 creatures. A spatial index waits until worlds grow.
- Some behavior only shows over hours of real time (sleep and the day cycle). The fixed time-of-day setting and the speed multiplier make it testable by hand.
